# FriendDrop 网页版设计（用户已确认）

## 目标与已确认范围
朋友之间通过网页快速传文件，包含美国与中国之间的使用场景；无需安装，单文件最大 3 GB（3,000,000,000 字节），优先使用 P2P，并优先使用免费服务额度。网页托管选择 GitHub Pages。跨国速度、连接成功率和移动端大文件能力必须实测，不视为已实现。

## 第一版体验
发送方打开网页、选择一个文件、创建邀请链接；接收方打开链接并确认文件名和大小、选择保存位置后开始传输。双方显示进度、速度、直连或中继状态，均可取消。房间仅允许两位参与者。双方保持页面打开；手机切后台或锁屏可能中断。
不做注册、好友系统、聊天、云端文件保存、多人广播或跨会话断点续传。连接中断明确报错，第一版重新发送。

## 方案比较与选择
纯静态页面加手动交换连接信息最省基础设施，但操作繁琐，且直连失败没有兜底。选用静态页面、独立信令和可选 TURN：邀请链接操作简单，文件仍优先直传。桌面程序暂不做。

## 结构与数据流
GitHub Pages 托管静态前端；独立 Cloudflare Worker 与 Durable Object 管理短期双人房间、WebSocket 信令及短期 TURN 凭证。文件内容不通过 Worker、GitHub 或房间存储。
WebRTC RTCDataChannel 传输分块文件，可靠有序通道配合发送缓冲背压和接收端落盘确认；不得一次读入整个文件。结束时校验总字节数及逐块完整性，接收端成功关闭写入后才向发送方确认完成。
直连使用 STUN；配置可用 TURN 后由 ICE 选择可用路径，界面如实显示选中的连接类型。没有中继配置时，直连失败显示原因和重试入口，不能假装已支持全网连接。

## 3 GB 与设备兼容
桌面支持文件写入 API 的浏览器优先直接写入用户选定文件。其他浏览器评估 OPFS 流式暂存、存储额度和最终导出能力；不得以最终拼接 3 GB 内存 Blob 作为默认方案。
接收前进行能力与空间检查。尚未通过完整大文件验证的平台不能宣称支持 3 GB；提供明确限制及桌面浏览器建议。手机基本传输和手机 3 GB 验收分开记录。大文件跨浏览器验收是产品目标，不靠隐藏限额宣称完成。
取消或中断清理应用临时存储；用户可见的未完成文件明确提示，不覆盖已有文件。

## 安全边界
高熵短期房间凭证放邀请链接 fragment，创建者与接收者权限分开。接收者声明原子化，限制两个参与者；加入后展示双方可比较的会话确认码。默认邀请 15 分钟过期；活跃传输不因邀请到期中断，断开后清理房间。
验证来源、凭证、信令类型与大小；限制建房和入房尝试。文件名按纯文本显示，拒绝非法大小和超限文件，不用远端文件名构造任意路径。WebRTC 提供传输加密；不得因此声称信令服务无法影响对端身份。
Cloudflare API 密钥只放服务端 secret，前端仅获得短期、受限 TURN 凭证。邀请链接按访问凭证对待，不写入日志或分析系统。

## 成本与上线
Cloudflare 官方当前 Realtime SFU/TURN 共享每月 1,000 GB 免费出口额度，超出后 $0.05/GB；Workers 与 Durable Objects 有独立额度与计费规则。免费额度不是零费用硬上限，部署前核对账户计划、用量与限制，不能把近似用量统计当成精确账单开关。
先在本地实现与验证，不在本阶段创建外部项目、启用付费、推送或发布。部署需配置用户账户与访问域名，并从美国和中国两端验证网页、信令和 TURN 的可达性。中继服务不可达时无法保证传输。

## 实施范围与验证
预计涉及静态界面、传输协议、接收存储、信令 Worker、房间控制、部署配置和测试。采用浏览器与平台 API；仅在必要的增量哈希等能力上使用经过评估的依赖，不构建无关通用框架。
检查空文件、中文文件名、3 GB 边界、超限拒绝、取消、异常信令、第三人入房、邀请过期、背压和接收端写入失败。浏览器双端测试传输并核对文件哈希；3 GB 测试同时观察内存。强制 relay 测试单独验证 TURN。中美真实设备、移动端后台和不同浏览器的结果逐项记录，不能用本机双窗口代替。
